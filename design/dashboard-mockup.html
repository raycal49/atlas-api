Visual refinements

  1. Track is a light step of the fill's own ramp, not neutral grey — compare the blue, amber and red tracks.
  2. Status never rides on color alone — amber and red rows carry an icon and a written label.
  3. Counts are compacted — 41.2K / 50K, not 41200 / 50000.
  4. The period is stated in words, so "1,284 calls" has a timeframe attached.
  5. Text wears ink tokens, never the data color. Only meters and badge icons are colored.
  6. Meters are 10px with a 4px rounded data end, square at the baseline.

Data behind it

  • Every value comes from /usage/me and /plans, which you already have. No new queries.
  • Calls this period is a client-side sum of calls_used; in 19 days is next_bill_due minus today.
  • Directions at 0 is the case your simplified SQL leaves out of the result and the service fills in with ?? 0.
  • APIs are listed alphabetically because findPlanApiLimits ends in ORDER BY ap.api_name — without it, row order between page loads is not guaranteed.
  • Plan, APIs and limits match the Developer tier in src/scripts/seedUsage.js, so a seeded database renders this shape.
